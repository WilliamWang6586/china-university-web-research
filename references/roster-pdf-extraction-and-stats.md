# 官网名单类 PDF/表格的批量提取与统计（2026-09 实测，吉大 2027 推免）

场景：从官网扒下来的公示附件是**拟录取名单 / 综合排名表 / 复试成绩表**，要答"今年数据怎么样"。
本文件是 `china-university-web-research` 的第四阶段（提取 + 统计），前三阶段见 SKILL.md。

## 0. 分阶段流水线（关键：每阶段落盘，可单独重跑）

```
_tm_probe.py    探针：站点可达性 + 是否真有今年条目（只探不下）
_tm_scan.py     清单：遍历各学院 → 列表页翻页 → 收通知 URL + 附件 URL → _tm_index.json
_tm_fetch.py    抓取：逐通知页取正文摘要 + 附件清单 → 汇入 _tm_index.json
_tm_download.py 下载：读 _tm_index.json → ThreadPoolExecutor(5) 并行下载 + 魔数校验 → _tm_dl.txt
_tm_extract.py  提取：按扩展名分派解析器 → 每个附件一份 .txt → _manifest.json（含 len/pages/sheets）
_tm_stats.py    统计：读提取层 → 出结论数值
```

**为什么必须拆**：本次 105 个附件，任何一步和下载合并都会超时；且每个阶段产物都是可复查的落盘证据。
**别省 probe**：第一轮先确认"今年条目真的存在"，否则整条流水线跑完发现扒的是去年的。

## 2. 图片版 PDF（扫描件）→ OCR 兜底

**判据**（不要凭猜测，直接探）：
```python
d = fitz.open(p)
lens = [len(pg.get_text()) for pg in d]      # 全为 0 → 无文字层
imgs = [len(pg.get_images()) for pg in d]    # 每页有 1 张整页图 → 确认是扫描件
```
本次吉大计算机科学与技术学院「2027年推免生拟录取名单.pdf」即此情况（2 页、`lens=[0,0]`、`imgs=[1,1]`）。

**处理**：`pg.get_pixmap(dpi=180).tobytes("png")` → base64 → 送 `qwen-vl-max`（DashScope 兼容端点）。
- key 从 `<配置目录>/.env` 的 `DASHSCOPE_API_KEY` 读
- **dpi 180 够用**；prompt 里明确"逐行输出、字段用 | 分隔、不遗漏、不编造"
- 模型会自作主张加说明文字 → **用正则 `^\|([^|]+)\|([^|]+)\|([^|]+)\|([^|]*)\|$` 抽表格行，再过滤表头行**，别直接当数据用

⚠️ **OCR 结果要跟同类官方文件交叉核对**（本次：OCR 抽 92 行，与另一个学院同类名单的字段结构对比确认列含义），别把 OCR 数字当一手精确值对外报。

## 3. 统计脚本的坑

- **`'拟录取' in line` 计数 ≠ 人数**：表头、备注列都含该词，且 `候补` 行不含。本次首次统计出 "拟录取 46 条" 而实际 42 人。
  正确做法：**按列 split 后取"录取结果"列做条件**，或按专业代码分组计数。
- **PDF 的 `get_text()` 是一行一个单元格**（不是一行一条记录）。要组记录就按 `序号 → 姓名 → …` 的位置偏移窗口取：
  ```python
  for i, l in enumerate(lines):
      if re.match(r"^\d+$", l) and re.match(r"^\d{6}$", lines[i+5]):
          rec = (int(l), lines[i+1], lines[i+3], lines[i+5], ...)   # 按偏移量取
  ```
  先用 `lines[:14]` 打印表头，**确认列偏移后**再写取值下标——本次先打表头这一步省掉了整轮返工。
- **专业代码 → 名称映射**要从同批文件里抽（复试名单的 `代码/名称` 相邻行），别硬编码。
- **`os.listdir` 提取层用扁平命名**（见 SKILL.md），且用 `if pat in filename` 做模糊匹配选取，避免拼接路径时反斜杠转义踩坑。

## 3b. ⚠️ 两种名单天差地别：先分清「接收」和「推出去」（2026-09 被用户当场纠正）

吉大的推免公示里有**两类完全不同的名单**，混淆会被用户抓住：

| | A. 接收名单（招进来） | B. 推免资格名单（排出去） |
|---|---|---|
| 标题特征 | 「**接收**推荐免试研究生拟录取名单」「复试名单」 | 「**拟推荐**优秀应届本科毕业生免试攻读研究生名单」「综合素质排名」 |
| 表头判据 | 有 **「本科毕业学校/本科院校」** 列 | 有「学号/班级/平均学分绩点/综合排名」，**无本科校列** |
| 人是谁 | 含大量外校生（本次汽车学院 365 人里外校 298，占 82%）| **全是吉大自己人** |
| 回答什么 | 吉大某院招了多少人 | 谁能拿到推免资格 |

**判据只要一行**：`"本科毕业学校" in text or "本科院校" in text` → 是 A（接收）；否则看有没有「学号+平均学分绩点」→ 是 B（资格/排名）。

**最容易被混的两组数**（本次报告初稿就因此被用户质疑）：
- 「交通学院录取 45 人」= **A**（本院接收，含外校）
- 「交通学院 277 人、绩点 3.86、加分 0.4」= **B**（本院本科生排名，是资格基数）

**B 类只公示"谁能拿到资格"，不写去向**——学生去哪由本人填教育部推免系统 + 对方学校录取。**"推免出去去了哪"要到教育部系统开放后、由接收学校公示才有**，此时在吉大官网找不到，要明确告诉用户。

## 3c. ⚠️「获得推免资格人数」多数学院根本不公示（2026-09 实测）

用户问「各专业拿到推免资格人数」时，**别默认它能扒到**。吉大各院公示方式自定：

| 公示形态 | 实例 | 能否得资格人数 |
|---|---|---|
| 「拟推荐名单」（带推荐意见列）| **仅法学院**（84 拟推荐 + 8 备选推荐）| ✅ 能，直接数「拟推荐」「备选推荐」 |
| 只发「综合排名表」（全专业逐人列）| 交通 / 汽车 / 物理 / 通信 / 地球科学 | ❌ 不能，切线第几名不外传 |

**做法**：先全盘 grep 标题含 `拟推荐|获得.*资格|推荐名单` 的文件，有就统计，没有就**直说没有**，并给出替代方案：
1. 等各院补发「拟推荐名单」
2. 等**学校教务处/研究生院 10 月统一公示**《推荐免试研究生名单》——全校总表，含各院各专业名额（最权威，务必告诉用户何时可补抓）

**辅助推断**：若某院发了「复试入围名单」而没发资格名单，可把入围名单的名字回查综合排名表——能反推大致资格线（切到第几名/对应绩点），但要标注「推断值非官方」。

## 3d. 往届数据回填：答案就在同一个列表页里（2026-09 实测）

用户问完「今年」几乎必然追问「**往届的呢**」。**不要去档案馆、不要等统一公示**——各学院官网的通知公告是**全量历史归档**，往届名单就在同一个 `tzgg.htm` 里，只是埋得深。

**关键数字**：吉大汽车学院 `tzgg.htm` **共 924 条 / 65 页**，2022 届的推免名单在第 30+ 页。交通学院 25 页。

**正确做法（三步，别省第一步）**：

```python
# 1) 翻完所有页，只收标题命中"推免"的条目（带日期）
for p in range(1, npages+1):
    u = base + "/tzgg.htm" if p == 1 else "%s/tzgg/%d.htm" % (base, p)
    h = get(u)
    rows = re.findall(r'<a[^>]+href="([^"]+\.htm)"[^>]*>\s*([^<]{4,110}?)\s*</a>'
                      r'[\s\S]{0,400}?(\d{4})[-/年](\d{1,2})[-/月](\d{1,2})', h)
    for hr, t, y, mo, d in rows:
        if re.search(r"推免|推荐免试|免试攻读|保研|拟推荐", t):
            记录(y, t, hr)
```

- 页数上限从列表页的 `共 N 条` 或 `tzgg/65.htm`（尾页链接）读出，别硬编码
- **年份反直觉**：`推荐2026年` 的公示发布于 **2025-09**。按发布时间过滤会漏，按标题里的届次分类才对
- ⚠️ 关键词 `推荐` 会大量命中奖学金/奖学金拟推荐人（**几百条噪声**），必须收紧到 `免试攻读` 或 `拟推荐名单` 组合

```python
# 2) 只对"名单类"标题开详情页（拟推荐/备选推荐/综合成绩排名/学业成绩排名）
# 3) 附件成对提取：webplus 的"附件【名】"锚文本与 download.jsp 链接常不相邻
```

**坑：附件名与下载链接不相邻 → 配对正则 `附件[【名】][\s\S]{0,400}?href=` 命中 0**（本次三个页面全 0）。
**解法**：把两种 token 塞进同一个文档序流，再按索引配对：

```python
toks = []
for m in re.finditer(r'附件[【\[]\s*([^】\]]{4,160}?)\s*[】\]]'
                     r'|href="(/system/_content/download\.jsp\?[^"]+)"', h):
    toks.append(("N", m.group(1)) if m.group(1) else ("L", m.group(2)))
links = [v for k, v in toks if k == "L"]
names = [v for k, v in toks if k == "N"]     # 可能为空，用 attach%d 兜底
```

**多列 + 全页水印的 PDF 计数（本次最大的坑）**：往届名单 PDF 有两类版式，且**每页有几百个「汽车工程学院」水印词**（一页 349 行里大半是水印），按行数或按序号数都会错 2~3 倍。三类版式与对应计数法：

| 版式 | 实例 | 计数法 |
|---|---|---|
| 单列 `序号 学号 姓名 专业` | 2025 届 | `re.findall(r"(?m)^\s*(\d{1,3})\s+(\d{8})\s+", t)` |
| **双列**（左右并排两组字段，text 抽取后交错） | 2024 届 | 学号计数 `len(re.findall(r"\b\d{8}\b", t))` |
| 分专业多文件（每文件即一个专业）| 2026 届 | 每文件学号计数 = 该专业人数 |

**万能兜底 = `len(re.findall(r"\b\d{8}\b", text))`**：每行恰好一个 8 位学号，水印词不含数字，天然免疫。
⚠️ 若某页名单位置被版式截断（本次 2026 届车辆工程第 2 页），学号计数会偏低 → **必须标注「下限估计」**，不能当精确值报。

**产出结论**：往届数据的最有价值输出是**专业级名额表 + 资格线**。本次从 2026 届备选名单的「排名」列直接读出：正式名单排到专业第 43 名、备选递补 44~72 名 → 车辆工程资格线 ≈ 第 43 名。**这个数比"共 83 人"有用得多**——备考的学生要的是线在哪。

## 4. 出结论的口径（用户要的是"数据怎么样"）

不要罗列抓到了几个文件。要出**可核对的数值 + 对用户的直接含义**：
- 总盘子（政策比例、合格线、时间线）
- 本院：基数人数 / 各专业人数 / 录取数 / 复试成绩区间
- 目标院：入围人数 / 本校 vs 外校占比 / 分数区间
- 横向对比表（各学院拟录取人数）
- **规律提炼**（本次三条：加分权重大、复试制非排名制、专硕是招生主力）
